# Prop Forge

Props generated by code usually look fake for the same few reasons: proportions guessed instead of measured, knife-sharp
edges, parts that float or intersect, one texture stretched at the wrong scale, perfect regularity, and nobody looking
at the result under real light before calling it done. This skill removes those causes one by one: build the object the
way it is made, at its real size, from a script you can re-run; dress it in photographed CC0 materials at true scale;
then judge it on rendered pictures and measured numbers, fix what they show, and only then export.

Hold yourself to evidence. "Looks good" means nothing until a review sheet has been rendered and read, and "correct
size" means a number from `check.py` compared with the brief.

## The loop

| Step | You produce | Gate before moving on |
|---|---|---|
| 1 Brief | `brief.md`: what, real dimensions and their source, parts, materials, how it is seen | every size has a source |
| 2 Blockout | `build_<name>.py` with primary masses only | `check.py --expect` within 5%; clay sheet reads as the object; silhouette vs reference if one exists |
| 3 Construction | the real parts, joints, bevels, gaps, variation | clay sheet: nothing floats, nothing is a plain box that should not be |
| 4 Surfaces | CC0 materials at true scale | texel density even; grain runs the right way |
| 5 Wear | `F.bake(...)`: one material, wear from the shape | wear reads right on the sheet (props seen alone or close) |
| 6 Review | numbered critique of each sheet, fixes in the script | a pass with no critique above "minor", or 6 passes |
| 7 Export | `.glb` + manifest | `check.py` passes; warnings fixed or explained |
| 8 Engine | the project's own import | seen in an engine screenshot |

Run steps 2 to 6 as many times as needed; they are cheap (bake last, once the form has settled: it takes a minute or two). Keep everything in the build script so each round is a re-run,
never a hand edit.

## Tools

All in `scripts/` beside this file. Blender scripts run headless through `run.py`, which finds Blender and prints only
the result lines (JSON):

```
python <skill>/scripts/run.py build_stool.py -- out/            # your build script (uses forge.py)
python <skill>/scripts/run.py review.py -- out/stool.glb --out out/review/sheet.png [--clay] [--ruler] [--game 9,4.5,40,1080]
python <skill>/scripts/run.py check.py -- out/stool.glb --expect 0.34,0.34,0.45
python <skill>/scripts/run.py silhouette.py -- out/stool.glb --ref-model ref/stool_scan.gltf --view front
python <skill>/scripts/run.py measure.py -- ref/stool_scan.gltf      # a reference's size and height profile
python <skill>/scripts/fetch_cc0.py search oak planks           # plain Python, no Blender
python <skill>/scripts/fetch_cc0.py texture oak_veneer_01 --res 2k --out textures
```

| Script | What it does |
|---|---|
| `forge.py` | the modelling library your build script imports: `begin`, `pbr`/`flat`, `box`, `cyl`, `lathe`, `extrude`, `soft`, `sphere`, `bevel`, `deform`/`sag`/`lumps`/`jitter`, `mirror_x`, `join`, `origin_bottom`, `bake`, `export`. Read its docstrings once before the first build. |
| `forge_bake.py` | what `F.bake` runs: a unique UV atlas, the photo materials and wear baked into one texture set (albedo, ORM, normal) and one material. |
| `measure.py` | a reference model's size and its profile in height bands (width, depth, radius): numbers for the brief and for lathe profiles. |
| `review.py` | Cycles review sheet of the exported file: three-quarter, front, side, top, close detail, and optionally the game's view at true pixel size (`--game DIST,HEIGHT,VFOV,SCREEN_H`) and a 1.75 m figure for scale (`--ruler`). `--clay` for form only; `--light warm` or `dim` for moody games. |
| `check.py` | re-imports the export and checks size, ground contact, floating and inside-out pieces, swapped or missing textures, triangle budget, texel density, power-of-two images, and the manifest. |
| `silhouette.py` | outline vs a reference model (true size) or photo (proportions): IoU and ten band widths. |
| `fetch_cc0.py` | searches and downloads Poly Haven / ambientCG CC0 textures (with their real-world size) and reference models. |

Copy `assets/build_template.py` to start a build script and `assets/brief_template.md` to start a brief.
`examples/` holds finished build scripts to learn the style from.

If the blender-* skills are installed, `blender-asset-qa` adds deeper checks (z-fighting between surfaces) and
`blender-texturing` adds decals and trim sheets. Neither is required.

## 1. Brief

Fill `brief.md` before modelling. The point is to have numbers to check against: proportions are where generated
models go wrong first, and no amount of detail rescues a wrong proportion.

- **Size**: take it from `references/dimensions.md`, from a measured CC0 scan of a similar object (`fetch_cc0.py search
  <word> --models`, `fetch_cc0.py model <id>`, then `measure.py` on it for its size and profile), or from the user's
  reference. Write the source next to each number.
- **Seen how**: camera distance and angle, and how tall the prop will be on screen in pixels. A prop 60 px tall needs a
  strong silhouette and clear value blocks; one filling the screen needs edge wear and texture detail. If the user
  doesn't say, assume a third-person or side view at 4 to 10 m on a 1080p screen and say so.
- **Parts in build order**, as a maker would list them: "two side panels, a top with a moulded edge, three drawers,
  brass pulls, a plinth". `references/recipes.md` has construction notes for common prop families.
- **Materials**: name the CC0 texture for each (search with `fetch_cc0.py`), and the plain values for small metal or
  glazed parts.
- **Variants**: how many and what varies (size, wear, colour, contents).
- **Budget**: triangles and texture size, from the user or the engine (`references/engines.md`).
- Ask the user only what the request can't tell you (target engine, camera, style if unclear); otherwise state your
  assumption in the brief and go.

## 2. Build script

One script per prop or family, `build_<name>.py`, written against `forge.py`. Conventions: metres, Z up, front facing
-Y, origin on the floor at the middle of the footprint, rotations in degrees.

- Put every dimension at the top as a named constant with a comment saying where it came from.
- One function per part, named for the real part (`leg`, `apron`, `drawer`, `page_block`), placed relative to the parts
  it joins, so changing one size moves everything that depends on it.
- Take a `seed` and draw all variation from `rng = F.begin(...)`, so variant 3 is the same every time.
- Never edit an exported file by hand. Change the script and re-run it.

## 3. Blockout, then construction

Blockout: the primary masses only, at brief size. Export, then `check.py --expect X,Y,Z` and
`review.py --clay --ruler --views three_quarter,front,side`. If there is a reference model or photo, run
`silhouette.py` (blockout gate: IoU at least 0.85 and every band within 0.05). Fix proportions now.

Construction: replace masses with the parts the object is actually made of, following these rules (the reasons and
numbers are in `references/realism.md`; read it before the first construction pass):

1. **Bevel every edge.** Width by material: hardwood 2 to 4 mm, worn edges 5 to 10, machined metal 0.3 to 1, cast metal
   1 to 2, stone 3 to 15. A knife edge is the strongest sign of a computer model.
2. **Real thicknesses.** Generated models are usually too thick everywhere. Check boards, legs, rims and covers against
   `references/dimensions.md`.
3. **Parts join, they don't hover or pass through.** A leg meets the apron, a book rests on the shelf, a lid sits on its
   box. Ground contact is exact (z=0).
4. **Gaps and reveals.** 1 to 3 mm around drawers and doors, page blocks inset from the covers, a shadow line where a
   lid meets its box. Gaps are what make an object read as assembled.
5. **Nothing is perfectly regular.** Jitter positions by 1 to 3 mm and angles by under a degree (`F.jitter`); vary
   repeated parts by a few percent; lean, sag and bulge where gravity or use would (`F.sag`, `F.lumps`, `F.deform`).
6. **Curves get enough sides** for their size on screen (a peg 8 to 12, a leg 16 to 24, a barrel 48 or more).
   `F.cyl` picks a count from the radius.
7. **Detail matches distance.** Anything under about 2 px in the game tile is noise; leave it to the texture.
8. **Wear tells a story.** Rounder, smoother edges where hands touch; scuffs low down; darker crevices. Model the shape
   change; give touched parts their own lower-roughness material when it is worth a material.

## 4. Surfaces

- Find a photo material with `fetch_cc0.py search <words>`; download it with `fetch_cc0.py texture <id>`. Its `info.json`
  gives `metres`, the real width one repeat covers: pass it to `F.pbr(..., metres=...)` so the grain is true to size.
- Open the albedo once and set `grain="u"` if the grain or weave runs across the image, `"v"` if up it. `forge` lays it
  along each part's length (box parts) or axis (turned parts).
- Use `tint` to vary hue and value between parts and variants (5 to 15%), not a new texture per part. Every part also
  gets a random patch of the photo (`rng=`), so neighbouring boards don't repeat.
- If a photo has big stains or uneven lighting that read as camouflage on small parts, `F.pbr(..., flatten=0.5)` takes
  them out and keeps the fine detail.
- Small metal, glass and glazed parts: `F.flat` with values from `references/materials.md` (base colour there is linear).
- `forge` writes the asset's own copies of every image, named `<material>_<kind>`, power of two, at most `max_tex`
  pixels: an engine reads plain images, and unique names stop glTF writers from swapping same-named files.

## 5. Wear: bake it into one material

Tiling photos can't carry wear that belongs to one spot: grime in this corner, the rubbed front edge of that lid,
dirt splashed up the bottom. Once the form and materials are right, call `F.bake(...)` just before `F.export()`:

```
F.bake("worn")                                    # presets: none, light, worn, old
F.bake("old", dust=0.5, density=1024)             # adjust one kind of wear; aim for a texel density
F.bake("light", groups={"candlestick": holder_parts, "candle": candle_parts})   # separate objects, one atlas
```

It unwraps all parts into one atlas, bakes what the photo materials show, then bakes masks from the geometry
(occlusion, convex edges, facing, height, noise) and mixes wear in: crevices darker and rougher, convex edges lighter
and smoother where hands rub, dirt near the floor, dust on what faces up, broad tone variation. The prop leaves with
one material (albedo, ORM with occlusion in R, normal), so one draw call. Choose the preset from the brief's story:
`light` for kept things, `worn` for used ones, `old` for neglected ones. Judge the result on the review sheet, close up
and under the game's light; each kind is adjustable (`edges`, `grime`, `ground`, `dust`, `variation`). Pass
`debug=True` to save the masks beside the textures when wear lands in the wrong place.

When not to bake: families drawn in great numbers (books on shelves, planks, bricks) are cheaper with shared tiling
materials, and so are props that must tile or deform. The atlas spends pixels on hidden faces too, so cut faces nobody
sees before baking when the budget is tight.

## 6. Review

Render the sheet from the exported file and look at it with the Read tool. Do this after every change worth seeing:

```
python <skill>/scripts/run.py review.py -- out/name.glb --out out/review/sheet.png --ruler [--game ...]
```

Also render it under the game's mood (`--light warm` or `dim`) when the game is dark, and `--clay` when judging form.
Then write a numbered critique, one defect per line, each with **where, what, a measurement, and the fix**:

```
1. [major] front: drawer fronts sit flush with the carcass, no shadow line. Inset them 2 mm, gap 2 mm.
2. [major] game tile: legs are 2 px wide and vanish against the floor. Radius 0.018 -> 0.024 m.
3. [minor] detail: top's grain repeats every 0.9 m; use the 2 m texture or a random patch per board.
```

Fix in the script, rebuild, re-render, re-critique. Stop when a pass yields nothing above "minor", or after six passes;
then report what remains. `references/review.md` has the checklist to read a sheet against: silhouette, proportions,
construction, edges, surfaces, contact, readability and family consistency.

## 7. Check and export

`F.export()` writes `<name>.glb` and `<name>.manifest.json`. Then:

```
python <skill>/scripts/run.py check.py -- out/name.glb --expect X,Y,Z [--max-tris N]
```

`pass` must be true. Fix every error; fix each warning or say in the report why it stands. If the review sheet was
rendered before the last change, render it again: the sheet must show the file you hand over.

## 8. Into the engine

Hand the file over the way the project already brings models in: read its CLAUDE.md, README or import scripts first.
`references/engines.md` covers Unreal, Unity, Godot and the web for projects without a pipeline. The prop is done when it
has been seen in the engine at the game's camera, not in Blender.

## Families and variants

When a scene needs many of a thing (books on shelves, bottles, crates, planks), build one script with a seed and export
variants: `for v in range(N): build(seed=v)`, each with its own name. Vary what varies in reality (height and thickness
of books, colour of leather, fill level of a sack) inside measured ranges. Share materials across the family so the
engine draws them in few batches. Show the family side by side in one review sheet (`review.py a.glb b.glb c.glb ...`).

## Report to the user

End with: the files written; size and triangles from `check.py`; materials and their CC0 sources; whether and how it
was baked (preset, atlas size, texel density); the last review sheet's
path (send it if you can); check result and any warnings left; what was inferred rather than measured; and what to look
at in the engine.

## Pitfalls (Blender 5.x and glTF)

- Run Blender with `-b --factory-startup` (run.py does). `F.begin` empties the scene and refuses to run in a live,
  interactive session.
- Same-named images (`albedo.jpg` from two folders) get renamed by the glTF writer and their contents can swap. `forge`
  names images uniquely; `check.py` flags a swap by looking at the pixels.
- Node maths between a texture and the shader (multiply, colour ramps) is lost on export. `forge` bakes tint and
  roughness changes into the images.
- Catmull-Clark subdivision turns boxes into blobs. Use `F.soft` (bevel, then simple subdivision) for padded things.
- Cloth simulation is unreliable headless. Drape cloth with `F.deform` and a shaping function instead.
- Bevel width is in object space: `forge` bakes scale into the mesh before bevelling. If you scale an object afterwards,
  call `F.bake_transform` before bevelling again.
- `material.use_nodes` is deprecated in 5.x; new materials already have node trees.
- glTF is Y-up; Blender's importer and every engine convert. Check orientation in the engine anyway.
- Bake once the shape is final: changing any part afterwards means baking again (re-run the script).
- The baked ORM's red channel is written as glTF occlusion, which Unreal, Godot and glTFast read.
